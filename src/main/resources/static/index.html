Качество поиска (eval)
Вопросы из dbo.rag_eval_question идут полным путём поиска (embed → Chroma → реранк → дедуп) без вызова LLM; метрика — recall: попал ли ожидаемый файл в выдачу (ранг = позиция в выдаче). Запускать после каждого изменения: chunk size, реранк, min-score, промпты. Клик по строке истории — детали того прогона; Δ — сравнение с предыдущим прогоном.

Ошибки индексации (последние 20)
Проиндексированные файлы (последние 200)
System-промпты лежат в dbo.rag_control и читаются перед КАЖДЫМ вопросом — изменения применяются сразу, без рестарта, на все инстансы. «Дефолт из кода» удаляет строку из таблицы: работает DEFAULT, зашитый в Java-классе (после рестарта он же просеется в БД). Ключи: ask_system_prompt · compare_system_prompt · summary_system_prompt · direct_chat_system_prompt (свободный чат) · extract_system_prompt / extract_json_schema (интеграция: файл → JSON; в схеме ключ — имя поля, значение — подсказка модели, может быть пустым).
Проверка извлечения на файле
Сохранили схему или промпт выше — проверьте на реальном файле. Схема и промпт читаются из БД перед каждым файлом, рестарт не нужен. Интеграторам: тот же endpoint — POST /api/rag/extract, поле 'file'.
Файл → /api/rag/extract → JSON по схеме из карточки выше.
